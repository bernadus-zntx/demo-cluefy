# Live intelligence feed

`GET /api/intelligence/live` returns up to 250 source records per response, plus `pagination.nextCursor` and `pagination.snapshot`. The first response also includes rules and recent crawler runs. To read the complete dataset, request subsequent pages with both `?cursor=<nextCursor>&snapshot=<snapshot>` until `nextCursor` is null. A page can contain fewer than 250 relevant items and still have a next cursor because relevance filtering happens after reading source rows.

The dashboard uses `shard=0..3` for four disjoint UUID ranges, with up to 400 source rows per page. It reads the first shard to establish the server snapshot, then fetches the remaining shards concurrently while paging each range sequentially. Every shard uses the same snapshot; all must finish successfully before the dashboard replaces its data. Unsharded clients, including the crawler, retain the original 250-row contract.

Pages use a descending UUID cursor and a fixed `first_seen_at` cutoff, so records inserted during a refresh do not shift page offsets. New records become visible on the next refresh. `LiveIntelligenceProvider` collects all pages before replacing the visible dataset and retains the previous dataset if any request fails. It sorts the collected items by publication/capture time. The crawler worker follows the same pagination contract for translation and enrichment backlogs.

Overview uses calendar dates in Asia/Makassar (WITA). The selected period and topic/sentiment/country filters feed the conversation total, trend, sentiment distribution, rankings, district view, and language analysis. Case/Finding operational queues retain their separate scope. Trend tooltips include zero-volume dates and unclassified sentiment. Ranges longer than 90 days use weekly buckets; ranges longer than 730 days use 30-day buckets, retaining the full selected total.

The Bahasa & Isu view groups actual language metadata, including an explicit unknown-language bucket. A selected language shows its sentiment and topic counts, prioritizing topics with negative conversations; clicking a topic shows recent source links. Missing or unclassified topics are excluded from the concern ranking. Language does not imply nationality. The shared Overview filters apply throughout. Trend tooltips appear on the plotted points and are placed above the plot.

Run `npm run test:overview` for pagination, date-boundary, filter-intersection, and aggregation regressions.

District analysis shows total volume and all four sentiment counts (positive, neutral, negative, and unclassified) with percentages based on all conversations. Hover/focus on a stacked bar or trend point reveals a breakdown; click a district name, total, or bar to open the village detail dialog. The dialog lists all administrative villages plus an explicit unmapped bucket, so its totals reconcile with the selected district even when village metadata is missing. Filters apply to both levels. Zero values reflect no matching stored records, not an absence of issues.

The 62-village hierarchy in `lib/district-analysis.ts` follows the [PN Denpasar administrative directory](https://pn-denpasar.go.id/tentang-pengadilan/wilayah-yurisdiksi). Mapping uses only location/village metadata and prefers specific names over substrings. General district names are not assumed to refer to the village of the same name; conflicting or ambiguous village metadata remains unmapped. No source records are modified.

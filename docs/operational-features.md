# Operational features: initial workflow

- The Verification and Escalation & Reporting choices in the demo login describe workflows only. The demo login does not authenticate users and the choices do not enforce permissions. Do not use them as production access controls. Real RBAC requires authenticated identities, server-side permission checks, and audit logging.
- Comment analysis reads `raw_payload.comments` when a source has provided an array of comments with `text`, optional `id`, `author`, `likes`, and a pre-existing `sentiment` (Positive, Neutral, or Negative). Counts cover captured comments only. Missing data is distinct from an empty list. This UI does not collect comments or classify their sentiment; a source integration and analysis pipeline are still required. Top comments are ordered by available likes.
- Daily, weekly, and monthly reports are manually generated for the latest 1, 7, and 30 Bali calendar days respectively, including today. The text download is generated in the browser. It is not a scheduled job, durable record, or automatic delivery. National issue notes are entered and reviewed manually; automated relevance detection is not implemented.
- Regional issue details can prepare a WhatsApp link with the selected issue, recipient type, user-entered number, note, and up to three source links. WhatsApp opens for user review and sending; the app neither sends messages nor records delivery or stores recipient details.
- Citra per Wilayah is based on the same matched leader-related content as the rest of the leader dashboard. Location is mapped from content metadata, not commenter identity. Sentiment is the content-level classification; actor-targeted sentiment is not yet verified.
- Issue and leader geography use the existing six-district, 62-village Badung mapping in `lib/district-analysis.ts`; ambiguous locations remain unassigned.
